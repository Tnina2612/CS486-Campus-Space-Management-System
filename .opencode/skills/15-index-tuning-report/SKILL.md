## Performance Evaluation & Tuning Methodology

### 1. Pre-Tuning Execution Baseline
For each of the 4 target queries:
- Clear buffer pool or run `UPDATE STATISTICS` to ensure fresh optimizer estimates.
- Enable statistics collection using T-SQL:
  ```sql
  SET STATISTICS IO ON;
  SET STATISTICS TIME ON;
  ```
- Capture the baseline metrics **without non-clustered indexes** (only PK/FK defaults):
  - **Logical Reads / Physical Reads** (page counts from `STATISTICS IO`).
  - **CPU Time & Elapsed Time** (ms from `STATISTICS TIME`).
  - **Execution Plan Operators** (e.g., `Table Scan`, `Clustered Index Scan`, `Key Lookup`).
  - **Estimated Subtree Cost** from the SQL Server execution plan.

### 2. SARGability & Query Refactoring Analysis
- Before creating indexes, check if queries are **SARGable** (Search Argument Able):
  - Avoid wrapping indexed columns in functions (e.g., `YEAR(start_time)`, `CAST(...)`, `ISNULL(...)`).
  - Ensure explicit inequality overlap logic (`start_time < @req_end AND end_time > @req_start`) is used instead of non-SARGable patterns.
- If refactoring is necessary, document the query improvement prior to index creation.

### 3. Index Design Strategy
For each query, design tailored T-SQL non-clustered indexes following SQL Server best practices:
- **Column Ordering Rule:** 
  1. Equality columns first (e.g., `space_id = @space_id`, `status = 'APPROVED'`).
  2. Range / Inequality columns next (e.g., `start_time`, `end_time`).
  3. Included columns (`INCLUDE (...)`) for non-key payload attributes to create **Covering Indexes** and eliminate expensive `Key Lookup` (Bookmark Lookup) operations.
- **Filtered Indexes:** Utilize `WHERE` clauses in index definitions when applicable (e.g., `CREATE NONCLUSTERED INDEX ... WHERE status = 'APPROVED'` or `WHERE impact_level = 'OUT_OF_SERVICE'`) to keep index size small and updates fast.
- **Trade-off Analysis:** Briefly note the potential impact of each index on DML (`INSERT`, `UPDATE`, `DELETE`) operations.

### 4. Post-Tuning Execution Benchmark
- Create the proposed indexes on SQL Server.
- Re-run the queries with `STATISTICS IO` and `STATISTICS TIME` enabled.
- Capture the new metrics:
  - Reduction in Logical Reads (%).
  - Reduction in CPU & Elapsed Time (ms / %).
  - Operator transition (e.g., `Clustered Index Scan` -> `Index Seek` + `Covering Index`).
  - Subtree Cost reduction.

### Section Structure per Query:
1. **Query Description & Business Context:** Purpose of the query and target execution frequency.
